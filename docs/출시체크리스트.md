## 0. 실기기 테스트 — **1차 완료 (2026-09-01, 갤럭시 S8)**

기기: **SM-G950N / 안드로이드 9 / 크롬 101**, 1080×2220 · density 480 → **CSS 360×약 630**.
웹뷰는 `com.google.android.webview 72` 가 깔려 있지만 **비활성**이고, 실제 제공자는
**`com.android.chrome 101`** 이다(2026-09-02 확인). 안드로이드 7~9 는 크롬이 웹뷰를 대신한다.
`adb reverse` 로 PC 의 로컬 서버에 붙여 크롬으로 열고 `adb exec-out screencap` 으로 화면을 확인했다.

🚨 **첫 실행에서 화면이 새하얗게 비었다.** 데스크톱 크롬에서는 멀쩡했다.
**실기기를 안 봤으면 그대로 출시할 뻔했다.** 원인과 수정은 아래 "구형 브라우저" 절에 적었다.

### 자동으로 확인한 것 ✅

`#app` 을 360×630 으로 줄여 **내기 점수 10점**(최악 조건)에서 게임 10개를 전부 계측했다.
`.half` 안 내용이 넘치는지, 어떤 요소든 화면 밖으로 나가는지 — **10개 전부 넘침 0**.

| 확인 항목 | 결과 |
|---|---|
| 위쪽 절반 180도 회전 | ✅ |
| 삼총사 카드 12장(3열×4행) 안 잘림 | ✅ |
| 같은 그림 찾기 원판 2개 세로로 들어감 | ✅ (겹치는 그림 1개도 확인) |

### ⚠ 구형 브라우저 — 여기서 두 번 깨졌다

**웹뷰가 크롬보다 훨씬 낡다.** 이 S8 은 크롬 101 인데 **웹뷰는 72** 다.
Flutter 래핑은 시스템 웹뷰를 쓰므로 **앱은 크롬이 아니라 웹뷰 기준으로 봐야 한다.**

1. 🔴 **`#app{height:100dvh}` → 화면이 완전히 백지.** `dvh` 는 크롬 108+ 다.
   101 은 이 선언을 통째로 버려 `#app` 높이가 `auto` 가 되는데, 자식 `.screen` 이 전부
   `position:absolute` 라 높이에 기여하지 않아 **높이 0** 이 된다.
   → **`position:fixed` + 네 변 고정**으로 바꿨다. `vh` 를 아예 안 쓴다.
   (`100vh` 폴백도 답이 아니었다 — 모바일 크롬의 `100vh` 는 *주소창이 숨은 큰 뷰포트* 라
   주소창이 보이는 동안 아래가 잘린다. 실제로 흰 띠가 생기고 캐릭터가 잘렸다.)
2. 🟡 **`inset:0` 은 크롬 87+** — 웹뷰 72 에서 안 먹는다. `top/right/bottom/left` 로 풀었다.

아직 남은 웹뷰 72 위험(치명적이지 않아 두었다): **flex `gap`(84+) 16곳**, **`:focus-visible`(86+)**,
**CSS `min()`(79+) 2곳**. 간격이 좁아지거나 포커스 테두리가 안 나오는 정도다.

📌 **2026-09-02 APK 로 확인한 결과, 이 기기에서는 셋 다 문제가 안 된다** — 위에 적었듯
활성 웹뷰 제공자가 웹뷰 72 가 아니라 **크롬 101** 이기 때문이다.
⚠ 하지만 **위험이 사라진 게 아니다.** 크롬을 안 깔았거나 낡은 사용자 기기에서는
`com.google.android.webview` 가 그대로 쓰인다. `minSdk 24`(안드로이드 7)까지 받으므로
훨씬 낡은 웹뷰도 들어온다. **웹뷰 72 를 활성으로 바꿔 한 번 확인해 두는 게 안전하다:**

```bash
adb shell cmd webviewupdate set-webview-implementation com.google.android.webview
# 확인 후 되돌리기
adb shell cmd webviewupdate set-webview-implementation com.android.chrome
```

### ⚠ 스크린샷·설명문 만들 때 지킬 것 (저작권·상표)

게임 **규칙**은 저작권 대상이 아니라 빌려 써도 되지만, **표현과 이름**은 다르다.
사고는 거의 전부 아래 두 곳에서 난다.

1. **남의 브랜드명을 한 글자도 쓰지 않는다.**
   `SET` · `도블` · `Spot It` · `할리갈리` 를 스토어 제목·설명문·스크린샷 문구에 넣지 말 것.
   "○○ 같은 게임" 같은 비교 표현도 안 된다 — 구글플레이가 명시적으로 금지하고,
   룰을 빌린 사실을 스스로 증거로 남기는 셈이 된다.
   (게임 이름을 `삼총사` · `같은 그림 찾기` · `딱 다섯` 으로 직접 지어 둔 이유가 이것이다.)

2. **스크린샷은 안드로이드에서 찍는다.**
   게임 카드에 이모지를 쓰는데, **이모지 그림은 플랫폼마다 저작권자가 다르다.**
   안드로이드(Noto Color Emoji)는 오픈 라이선스지만 **애플 이모지 그림은 애플 저작권**이다.
   앱 안에서 시스템이 렌더링하는 건 문제없고, **아이폰 화면을 캡처해 스토어에 올리면 문제**다.

나머지는 이미 깨끗하다 — 글꼴은 SIL OFL(Jua · Gothic A1), 소리는 WebAudio 로 생성해
음원 파일이 0개, 아이콘·캐릭터는 도형으로 직접 그렸다. **외부에서 가져온 소재가 없다.**

## 4. Flutter로 감싸기 (안드로이드) — **APK 빌드·설치·동작 확인 완료 (2026-09-02)**

절차는 `flutter/README.md`에 단계별로 정리해두었다. 실제로 돌려 보고 겪은 함정도 거기 적었다.

빌드 환경: **Flutter 3.44.6 · Android SDK 36**. 결과물 `app-release.apk` **42MB**
(모든 ABI 가 든 범용 APK 라 크다. 스토어에 올릴 **AAB 는 기기별로 쪼개져 훨씬 작다**).

- [x] `applicationId` = `com.syaapps.kungjjak` — `--org com.syaapps` 로 자동으로 잡힌다
- [x] **target API 36** — Flutter 3.44 의 `flutter.targetSdkVersion` 기본값이 이미 36이라 손댈 게 없다
- [x] 앱 이름 `쿵짝` — `AndroidManifest.xml` 의 `android:label`
- [x] 화면 꺼짐 방지 — `MainActivity.kt` 에 `FLAG_KEEP_SCREEN_ON`
- [x] **앱 아이콘** — `web/icons/icon-512.png` 에서 mipmap 5종(48~192px) 생성.
      ⚠ 안 하면 홈 화면에 **Flutter 기본 파란 새**가 뜬다
- [x] INTERNET 권한 — **애초에 릴리스에 없다.** Flutter 는 이 권한을 `src/debug` 와
      `src/profile` 매니페스트에만 넣는다. 실제로 설치 후 확인한 요청 권한은
      Flutter 내부용 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` 하나뿐이었다
- [x] 뒤로가기 동작 — 게임 중 → 메뉴 ✅ / 메뉴 → "쿵짝을 끝낼까요?" 확인 창 ✅
- [x] **종료 창 색** — 머티리얼 기본 보라로 나오던 것을 팔레트에 맞췄다(커밋 `94e98f6`)
- [ ] 릴리스 서명 키 생성 후 **원드라이브 아닌 곳에 백업** (분실 시 업데이트 불가)
- [ ] `flutter build appbundle --release` → AAB 확인

### 오프라인은 구조적으로 보장된다

게임이 `file:///android_asset/` 에서 로드되고 **INTERNET 권한 자체가 없다.**
네트워크를 쓰고 싶어도 못 쓴다 — 비행기 모드 테스트보다 강한 증거다.
데이터 안전 양식에 "수집 없음" 을 자신 있게 쓸 수 있다.

### ⚠ 아직 스토어에 못 올린다 — 디버그 키로 서명돼 있다

지금 APK 는 Flutter 가 기본으로 넣는 **디버그 키**로 서명돼 있다. Play Console 이 거부한다.
**`flutter/README.md` 의 「7. 서명 키」** 를 먼저 해야 한다.

🔑 **키를 잃어버리면 이 앱을 영영 업데이트할 수 없다.** 새 키로 서명한 앱은
Play 가 같은 앱으로 인정하지 않아, 사용자를 두고 새 앱으로 다시 시작해야 한다.
그래서 **만들기 전에 어디에 백업할지 먼저 정한다.**
