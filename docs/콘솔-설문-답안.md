# Play Console 설문 답안 — 미리 만들어 둔 것

개발자 계정이 생기면 **이 문서를 보고 그대로 옮겨 적는다.**
콘솔 앞에서 처음 생각하기 시작하면 «대충 맞는 것 같은» 답을 고르게 되고,
설문 답과 앱 실물이 어긋나면 **정책 위반으로 앱이 내려간다.**

- 앱: **쿵짝** · 패키지 `com.syaapps.kungjjak`
- 개인정보처리방침: https://sya-apps.github.io/kungjjak/privacy.html
- 스토어 문구: `docs/스토어-등록정보.md`
- 작성 2026-09-03. **콘솔 화면의 실제 문항이 이 표와 다르면 화면이 맞다** — 문항은 수시로 바뀐다.

## 이 앱이 답하기 쉬운 이유 — 근거부터

거의 모든 문항이 «아니요» 인데, **그게 사실인지 확인할 수 있어야** 자신 있게 답한다.

| 주장 | 확인하는 법 |
|---|---|
| 네트워크를 안 쓴다 | `INTERNET` 권한이 **아예 없다**. Flutter 는 이 권한을 debug/profile 매니페스트에만 넣는다 |
| 서버가 없다 | `web/index.html` 에 `fetch`·`XMLHttpRequest`·`WebSocket`·`sendBeacon` 이 **0건** |
| 서비스워커도 안 돈다 | 등록이 `location.protocol.startsWith('http')` 로 막혀 있다. 앱은 `file://` 라 **아예 등록되지 않는다** |
| 외부 CDN 이 없다 | 글꼴까지 base64 로 파일 안에 박혀 있다 (`tools/embed_fonts.py`) |
| 기기에도 안 남긴다 | `localStorage`·`sessionStorage`·`indexedDB`·쿠키 **0건**. 내기 점수도 메모리에만 |
| 광고·분석 SDK 가 없다 | 의존성이 `webview_flutter` 하나뿐 (`app/pubspec.yaml`) |
| 결제가 없다 | 인앱 결제 라이브러리 없음, 유료 아님 |

### 권한 — **2026-09-03 릴리스 APK 에서 실측**

```bash
"/c/Android/Sdk/build-tools/35.0.0/aapt2.exe" dump permissions <릴리스 APK 경로>
```

```
package: com.syaapps.kungjjak
permission:      com.syaapps.kungjjak.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
uses-permission: com.syaapps.kungjjak.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
```

**요청하는 권한이 «자기 자신이 정의한 것» 하나뿐이다.** AndroidX 가 내부 브로드캐스트를
남이 못 받게 막으려고 만드는 것이라 바깥과 무관하다.
**`INTERNET` 도 `AD_ID` 도 없다** — 그러니 데이터를 «전송» 하는 것이 기술적으로 불가능하다.

📌 이 한 줄이 데이터 보안 설문의 가장 강한 근거다. 반려당해 이의를 제기할 일이 생기면
**이 출력을 그대로 보여 주면 된다.**

📌 구글의 정의: **«수집» 이란 사용자 기기에서 데이터를 «전송» 하는 것**이다.
기기 안에서만 처리되고 밖으로 안 나가는 것은 **신고 대상이 아니다.**
그러니 저장을 하더라도 «수집 없음» 인데, 쿵짝은 저장조차 안 한다.

## 2. 데이터 보안 (Data safety)

```
이 앱이 필수 사용자 데이터 유형을 수집하거나 공유하나요?   →  아니요
```

그러면 하위 문항이 전부 사라진다. 요약 카드에는
**«데이터가 수집되지 않음» / «데이터가 공유되지 않음»** 이 뜬다.

이어지는 두 문항:

| 문항 | 답 | 왜 |
|---|---|---|
| 전송 중 데이터가 암호화되나요? | (문항 자체가 안 나온다) | 전송하는 데이터가 없다 |
| 사용자가 데이터 삭제를 요청할 수 있나요? | (안 나온다) | 보관하는 데이터가 없다. 앱을 지우면 끝이다 |

🚨 **«기기에 저장하니까 수집이겠지» 라고 «예» 를 고르지 말 것.** 구글 정의상 아니다.
잘못 «예» 를 고르면 없는 데이터의 종류·목적·삭제 경로를 지어내야 하고,
그 순간 **설문과 실물이 어긋나 반려 사유가 된다.**

| 공포·무서운 요소 | 아니요 |

📌 **«도박» 은 한 번 더 생각할 것.** 쿵짝의 «내기 점수» 는 두 사람이 몇 점까지 겨룰지

## 4. 타겟층 및 콘텐츠 (Target audience and content)

```
대상 연령대  →  13세 이상만 선택.  🚨 12세 이하 구간은 절대 체크하지 않는다.
```

**왜 13세 이상인가** — 만 13세 미만을 하나라도 고르면 **Families 정책**이 발동한다:
광고 SDK 자가인증, 콘텐츠 모더레이션, 데이터 최소화 의무가 통째로 붙는다.
쿵짝은 아이도 할 수 있는 게임이지만 **아이를 «타겟» 으로 삼지 않는다.**

이어지는 문항:

| 문항 | 답 |
|---|---|
| 앱이 아동의 관심을 끌 수 있나요? (스토어 등록정보가 아동 대상으로 보이는가) | **아니요** |
| 아동에게 어필하는 요소가 있나요? | 아니요 |

⚠️ **구글은 «디자인과 문구가 아이 취향인가» 로도 판단한다.** 여기서 걸리면
설문 답과 무관하게 Families 로 분류된다. 그래서 지켜야 할 것:
- 스토어 문구에 «아이», «어린이», «유아», «초등» 을 쓰지 않는다
- 스크린샷에 아동용으로 읽힐 문구를 넣지 않는다
- 캐릭터가 둥글고 귀엽지만 **«아이용» 이라고 말하지 않는다** — 말하지 않으면 된다

## 6. 한국 개발자 추가 연락처 — **조직 계정이면 주소도 요구된다**

한국은 별도 요구가 있다: **업체는 «연락처 주소» 와 «문의 전화번호» 를 둘 다** 내야 한다
(개인은 전화번호만). 이 정보는 **한국 사용자에게만** 앱 설명 하단에 표시된다.

| 항목 | 넣을 값 |
|---|---|
| 문의 이메일 | `sya.apps.dev@gmail.com` |
| 문의 전화번호 | 담당자 번호 (**나중에 수정 가능**) |
| 연락처 주소 | 사업장 주소 — **동·호수를 뺀 도로명까지** |

🚨 **개인 메일(`baeissak@gmail.com`)을 어디에도 넣지 않는다.** 공개되는 곳은 전부 `sya.apps.dev`.

📌 **주소·상호는 조직 계정을 만든 뒤 수정할 수 없다. 전화번호·이메일·웹사이트는 된다.**
자세한 것은 `C:/SYA/CLAUDE.md` 의 「사업자(조직) 개발자 계정」 절.
